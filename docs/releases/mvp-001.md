# MVP-001 Release Notes

## Metadata
- MVP: `MVP1`
- Date: `2026-03-08`
- Status: `released`

## Summary
MVP1 stabilized the portfolio + local CMS foundation by unifying post sources, hardening security, adding local-first deployment controls, introducing operational backup automation, and expanding project documentation.

## Scope
- CMS and build pipeline reliability improvements
- Security baseline and environment validation
- Local-first deployment and operations tooling

## What shipped
- Unified canonical post source to `content/posts` and removed legacy source ambiguity.
- Updated build/template contracts so blog post rendering and metadata handling are consistent.
- Added environment preflight validation with clearer runtime/build errors.
- Added CSRF protection and login rate limiting in CMS auth flows.
- Added deploy adapter modes (`none`, `command`, `webhook`) with local-first defaults.
- Added backup tooling: manual backup, weekly cron support, and weekly systemd timer support with catch-up behavior.
- Expanded repository documentation with setup, API contracts, troubleshooting, and maintenance guidance.

## Behavioral changes
- CMS write actions now require valid CSRF token headers.
- Repeated failed logins are temporarily rate-limited.
- Publish/delete/save flows can run build-only mode without deployment (`DEPLOY_MODE=none`).
- Backups can be automated weekly through user-level systemd timers.

## Verification run
- `npm run build`
- `npm run admin`
- `npm run preview:dist`

## Known limitations
- Login rate limiting is in-memory and resets on server restart.
- Local filesystem remains the CMS datastore (no shared/persistent remote store abstraction).

## Follow-up seeds
- Add automated tests for CMS routes and build smoke checks.
- Add persistent/centralized rate-limit storage if multi-instance hosting is introduced.
