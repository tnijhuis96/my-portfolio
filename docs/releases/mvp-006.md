# MVP-006 Release Notes

## Metadata
- MVP: `MVP6`
- Date: `2026-03-28`
- Status: `released`

## Summary
MVP6 upgrades the local CMS into a practical authoring workspace. Drafts and scheduled posts are now first-class content states, the editor renders live markdown preview while writing, repeated tags are easier to reuse through autocomplete, and external image URLs can be previewed before inserting markdown.

## Scope
- Live markdown preview in the local CMS editor
- Draft and scheduled publish flow
- Tag autocomplete from existing content
- External image URL assist with inline preview

## What shipped
- MVP6 governance files and guardrails were created
- Admin server now supports draft status, schedule date, normalized tags, and tag-autocomplete data
- Admin editor now includes split live preview, draft/scheduled organization, and external image URL assist
- Static build now excludes drafts and future-scheduled posts from public output

## Behavioral changes
- Posts without a `status` field now default to published behavior to preserve older content
- `publishAt` gates public output when set to a future date, even if the post status is `published`
- `Publish Now` overrides a future schedule by normalizing `publishAt` to today
- The admin list separates published posts from drafts and scheduled work instead of mixing all states together

## Verification run
- `npm run build`
- `npm run admin`
- `npm run preview:dist`
- Temporary fixture posts verified draft exclusion, future-schedule exclusion, and published/legacy inclusion across blog index, tag pages, RSS, and sitemap
- Editor-side interactions were verified by source-path inspection of the shipped admin workflow in `admin/blog-editor.html`

## Known limitations
- Schedule behavior is based on the local machine date at build time
- External image support is URL-only; MVP6 does not add uploads or asset management

## Follow-up seeds
- Consider richer markdown authoring shortcuts after MVP6 stabilizes
- Consider asset-library support in a later milestone if external image URLs are not enough
